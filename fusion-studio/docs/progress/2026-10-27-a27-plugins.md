# A27 plugin registry — 2026-10-27

## Kernel

New `src/plugins.js`: the registry half of a plugin ecosystem —
manifest validation, host API compatibility, dependency ordering, and
permission bookkeeping. Per the plan rule, external plugin execution
waits for a permission model; this kernel **is** that model's registry
and deliberately never loads or executes plugin code.

- `validateManifest` collects every problem at once (id shape, semver,
  api window, unknown permissions, self-dependency, bad ranges) instead
  of throwing on the first.
- Minimal semver: `compareSemver` (numeric per component) and
  `satisfiesRange` for `*`, exact, `^`, `~`, `>=`, `<=`, `>`, `<`.
- `createPluginRegistry({hostApiVersion})`: duplicate ids and
  out-of-window API requirements are rejected at register time.
- Permission grant policies: `deny` (default, grants nothing),
  `declared-safe` (declared minus `files:*`/`network:*`), `all`, or an
  explicit list intersected with the manifest's declarations.
- `enableOrder()` topologically sorts dependencies first and reports
  cycles; `setEnabled` enforces dependency-enabled and version-range
  checks, and refuses to disable a plugin an enabled dependent needs.

## Verified (tests/plugins.test.mjs, 5/5)

Semver/range truth table (including numeric-vs-lexicographic
