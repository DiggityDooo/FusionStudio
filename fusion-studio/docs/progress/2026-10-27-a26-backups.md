# A26 auto-backup & recovery — 2026-10-27

## Kernel

New `src/backups.js`: backup naming, rotation policy, checksummed
storage, and recovery over an injected store (`list/write/read/
remove`), so the app can back it with the filesystem while tests use
the included in-memory store.

- `backupName(project, date)` produces sortable, filesystem-safe
  `Project_2026-10-27T14-30-05.fsn.bak` names; `parseBackupName`
  inverts them and rejects non-conforming names.
- `planRotation(names, {keepCount, keepDays})`: keep the newest N,
  plus the newest backup of each of the last D UTC days; unrelated
  filenames are ignored by both keep and delete lists.
- Backups are envelopes `{checksum, payload}` using FNV-1a (corruption
  detection, not cryptography).
- `restoreLatest` verifies newest-first and **falls back past
  corrupted backups**, returning the skipped names; total corruption
  returns null without throwing.

## Verified (tests/backups.test.mjs, 5/5)

Name round-trip and chronological sortability; rotation plan exactness
(newest-2 + two daily representatives kept, the 30-day-old and the
third-from-newest deleted; `keepDays: 0` collapses to the count
window); cross-project isolation; tampered newest backup detected via
checksum with fallback to the previous valid one; truncated-JSON
corruption reported, not thrown; manager-level rotation deleting per
plan while leaving other projects untouched.
