# A24 G-code emission for CAM toolpaths (2026-10-27)

Kernel: `src/gcode.js`. Tests: `tests/gcode.test.mjs` (4/4; the
existing `tests/toolpath.test.mjs` 5/5 unchanged).

`ringsToGcode` turns pocket/profile rings into an RS274-style
program: `%` wrapper, millimetres/absolute/XY-plane header, spindle
on, and per depth pass (`depthPasses`: stepdown levels clamped at
the final depth) each ring is rapid-positioned, plunged at the
plunge feed, cut closed at the cutting feed, and retracted to the
safe Z. `pocketGcode` / `profileGcode` compose the toolpath kernel
with the emitter. Motion statistics (cut/plunge/rapid distance and
a feed-based time estimate) are accumulated by simulating the tool
position during emission.

Oracle: the test carries an independent modal G-code parser
(shares no code with the emitter). Parsed cut distance equals
rings-perimeter × passes exactly, every parsed cutting endpoint is
a ring vertex, cutting Z levels are exactly the pass levels, the
tool never goes below −depth, and the parser-integrated motion
time reproduces the emitter's time estimate to <0.1%.

Limits: generic dialect only (no machine post-processors), linear
moves only (no arcs/drilling cycles), pass-major ring order, no
tool-change or coolant words.
