# A26 naming conventions & validation — 2026-10-27

## Kernel

New `src/naming.js`: data-driven scene naming rules and repair.

- `DEFAULT_RULES`: per-category conventions (mesh `_GEO`, material
  `_MAT`, light `_LGT`, camera `_CAM`, lowercase bones) with regex
  patterns, required suffixes, and a forbidden-character set. Custom
  rule sets replace the defaults wholesale.
- `validateNames(objects)` reports every issue — duplicates, charset,
  pattern, suffix — with fix suggestions where a mechanical fix exists.
  Blender-style `.001` duplicate suffixes are recognized and not
  flagged as pattern breaks.
- `makeUnique` follows Blender numbering (`Name`, `Name.001`, ...),
  re-basing numbered inputs.
- `sanitizeName` repairs a single name: case is normalized **before**
  charset replacement (a lowercase-only charset would otherwise eat a
  capital letter — caught by test), separators collapse, the category
  suffix is ensured.
- `applyFixes` renames a whole scene to a valid, unique state, keeps
  already-valid names stable, and is idempotent (verified by
  re-validating and re-fixing the result).

## Verified (tests/naming.test.mjs, 6/6)

Per-rule issue detection on a mixed scene; `.001`-numbered scenes
validate clean; sanitize repairs (charset/case/suffix, empty-name
fallback); unique numbering including re-basing; whole-scene fix
producing an exactly expected rename list that re-validates clean and
does not change on a second pass; custom lowercase rule set honored
without mutating the defaults.
