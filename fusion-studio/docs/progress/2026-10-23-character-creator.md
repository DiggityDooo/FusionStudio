# Character Creator: source checkpoint, October 23, 2026

Status: **0.19.0 development source, unreleased. The complete creator and unified-excellence goal are not finished.** Delivered 0.18.0 and earlier releases remain preserved.

## User request retained

The user requested a realistic adult male/female character generator **within Fusion**, with Blender-inspired shape keys, body/face proportions, many skin tones, hairstyle/color choices, artistic nude/underwear/clothed views and artistic poses. They explicitly approved the supplied Character Creator implementation plan: public redistributable assets and compatible private libraries, immutable topology families, body/face controls and isolated neutral shape authoring, skin/hair materials, clothing/posing integration, recovery and performance gates. Full-body and close-up results must both be convincing before packaging. Existing Electron/Three.js, native Rust geometry, installed persistent Blender worker, shared scene/history/projects and local processing remain the architecture. Original installations, private assets and previous releases must be preserved. No cloud generation, full grooming editor, publication or redistribution of paid content is included.

Implementation order remains foundation/recipes → body/face and shape authoring → appearance → clothing/posing → visual/recovery/performance gates. The user's later “continue with goal” authorizes continued implementation, not a research-only restriction.

## Implemented behavior

- Character workspace has adult female/male creation, seven creator tabs, **229** categorized sparse body/face controls, search, numeric input, reset, favorites, symmetry and randomization locks/seed. Height is in metres; normalized influences are distinguished from measured geometric torso sections.
- A versioned HM08 definition and recipe retain asset identity, source IDs, sparse targets, rig landmark data, weights, control values, user shapes, appearance, visibility, attachments and pose. Immutable source data is shared outside serialized history. Current foundation identity is `a096800b512ba42bec18e9ed6bef3a00c71cf8b394d3b9fd30c5444ebde56dd8`; compressed SHA-256 is `29671ddf4dd78f51302edebdd822cbce7f8c09bab02b15ead6023840f9ff31f2`. The prior development foundation is retained in the asset-version index for matching saved recipes.
- The canonical body uses **19,158 source vertices** including helpers, **26,756 rendered cage triangles** and material/UV source correspondence. Rig landmarks refit from evaluated source data while retaining authored rotations. Display attachments raise total triangle counts; counts do not represent scan detail.
- User shape keys support creation, naming, duplication, mirroring through an explicit source map, influence bounds/mixing, deletion and timeline keyframes. Authoring uses an isolated neutral, unposed copy with draw/smooth sculpt brushes. Direct face deletion/extrusion and component topology operations are rejected **before** modifying that copy. Apply also checks unchanged vertex order/connectivity and stores sparse rest-space deltas; Cancel/Escape and saving/export guards protect the original. This is not inverse-pose subtraction.
- Skin has 24 presets, continuous tone/undertone and roughness, approximate pore/freckle/age controls independent of facial geometry. Individually documented CC0 texture detail remains when tinting. Sclera, iris, cornea, brows/lashes and hair have separate materials. Starter bump is derived from albedo, not scanned displacement.
- General Material-panel body color, roughness and metalness now update the same recipe, remain confined to the body and survive reconstruction/reopening. Custom tints are indicated in Skin; choosing a palette tone clears the override. Generated eye/hair parts direct their color edits to their respective creator controls. This repairs a real persistence mismatch rather than saving a second conflicting material state.
- Hair presets use CC0 authored guides and seeded barycentric scalp correspondence. Short/long source guides derive medium/wavy/curly/coily display variants; **8,000 two-sided strand ribbons** give denser scalp coverage. Roots track head deformation; brow/lash/facial-hair guides are also available. This is a fitting preview, not full grooming or hair collision.
- Character display supports nude/underwear/clothed modes and anatomy coverage without replacing the body or skinning. Starter coverage is a body-derived shell, not a finished clothing asset. Existing Clothing tools create designed garments.
- Standing, contrapposto, seated, reclining, gesture and T-pose presets use explicit foundation bone axes. Existing FK/IK, authored joint limits, pose library and timeline remain available. New custom shapes key through the shared timeline.
- A typed character worker carries request/context identity; sparse results validate before application. Slider previews coalesce inside one gesture transaction. Body, rig, attachments and linked garment updates commit together; failures/cancellation/stale replies restore prior state.
- The render sidecar carries fixed object/material-ID parameters to Cycles. Preview subsurface/freckles are labeled approximations. Render subdivision is derived on the Blender job copy. GLB retains supported rigs/custom shapes, while Fusion recipes stay in projects. The export compatibility review explicitly warns that body/face controls, hairstyle bindings and generator recipes are evaluated for exchange, rather than silently promising editable generators in external formats.
- Public creator **body and strand buffers are derived outputs** in project snapshots, rebuilt from the matching foundation and recipe before replacing the active scene. Stable object/geometry/material/texture identities survive regeneration. **Painted bodies keep their authored geometry/weight buffers embedded**, rather than losing edits during reconstruction. Coverage refits after weight revisions. Other meshes and private imported bodies retain their existing persistence. Old projects with embedded creator buffers still load. Ordinary exchange always receives complete live meshes, not placeholders.
- Shared history interns unchanged image payloads while retaining original image identities. Changed pixels survive undo/redo; abandoned image entries can be pruned. Project files still embed textures and never require history-only references. The scene serializer reuses image encoding only while its source version/data are unchanged, and omits derived body/hair arrays before allocating JSON buffers. Returned documents own their mutable image arrays. Procedural iris detail is computed once and copied for each attachment. These changes reduce repeated work; they do not satisfy the full interactive latency target.
- HM08 fitted-shirt defaults use its verified `neck_01`, upper-arm and forearm mapping. Torso measurement axes use the neutral pelvis landmark: forward hands in the male base no longer displace the section axis. The same axis is carried through the grading worker. Existing imported-family mappings remain subject to visible review.

- `test-output/creator-garment-male-results.json`: **complete male workflow passes**, including visible joint review/cancel, curved six-panel draft/drape, linked body-height change, joint undo/redo, contrapposto refit, save/reopen and full-body Cycles rendering. Initial draft has 4,817 garment triangles, 25.95% maximum strain, 0.0793 mm mean seam gap, zero measured body intersections/inside vertices/clearance violations and no reported cloth-contact violations. The 20-iteration solve takes **65.5 s**, with no measured body/cloth contact violations and about 0.0587 mm mean seam gap. The worst stretch is across the front bust patch. The draft dialog now exposes solver iterations (creator default 20, imported-family default 10) rather than hiding the work budget. No tolerance was loosened.
- An explicit **8% uniform enlargement of retained panels was rejected**: maximum strain becomes 160.44%, mean seam gap 12.05 mm, with 63 body/cloth face intersections and 113 non-adjacent cloth crossings. It is a private test working copy, not a default or automatic repair. `creator-female-ease-probe-results.json` and the saved failure projects retain evidence. Further work must improve front-panel shaping, correspondence and contact; blindly adding global ease or solver work is not an established fix.
- `test-output/creator-performance.json`: warm synchronous sparse calculation on **conformingly refined copies of the actual body**, with 0/16/64 interpolated targets. At 64 targets, the 200k-triangle fixture has a **42.76 ms median / 56.30 ms maximum** across seven measured iterations. Refinement adds sampling density, not anatomical scan detail. Workers, history, normals, rig/attachments, garments and viewport FPS are excluded from this probe. End-to-end latency needs the separate desktop report.
- `test-output/creator-interactive-performance.json`: the final desktop probe at **1036×729 pixels** averages **54.97 fps** with 60,892 total triangles and **54.55 fps** with 428,892 triangles including 8,000 hair ribbons. Three completed height edits take **551.9–611.3 ms** bald and **697.2–730.3 ms** with hair, including worker transfer, geometry/rig/attachment evaluation, history and the next frame. Separately, three actual in-gesture warm previews take **157.2–168.2 ms** bald and **296.9–312.9 ms** with hair, from worker post to a subsequent visible frame, excluding the 100 ms debounce and gesture-boundary snapshots. **The requested 100 ms warm-preview target fails on both fixtures.** Direct arithmetic and typed-buffer writes remove temporary per-strand vectors/colors/arrays while retaining all 8,000 strands; the earlier hair previews measured 566–654 ms. These small fixture runs are not a guarantee for all 50k/100k/200k body meshes, long hair or multi-character scenes.
- `test-output/bmw-render-results.json`: the requested CPU/OptiX preserved-scene regressions pass. Mean absolute RGB-byte differences are approximately **0.00003472 CPU / 0.00003328 OptiX** at 640×360/16 samples. Source hashes/timestamps remain unchanged. The transformed-scene comparison is a separate non-invariant test; generic GLB shading remains approximate.
- Build passes with the existing large-bundle advisory. No new native binary was built by this creator checkpoint.

The visual inspection deliberately rejected earlier sparse hairstyle coverage and the male texture's painted dark eye sockets. Source CC0 guide interpolation now produces denser previews. The starter male texture now uses Toigo's bronze skin without that paint; the original Aksel source remains preserved. This is artistic curation, not proof of photorealism.

4. Complete private-library adapters beyond read-only base import: family-specific controls, source mappings, exact material interpretation, joint refits, hair compatibility, shape authoring and integrated clothing. Never transfer HM08 assets by matching a Genesis name.
5. Measure and optimize end-to-end body previews and orbit at increasing body sizes. The numerical <100 ms result does not satisfy the desktop target; attachment building and snapshot construction still perform main-thread work. Garment simulation remains asynchronous/offline. Continue failure/asset-relink and package-path checks on the complete workflow.
6. Version/migrate future derived algorithms and material recipes deliberately; preserve existing source assets. Package one integrated release only after the public/private and visual gates pass together. Do not relabel the old delivered release as containing source-only work.
