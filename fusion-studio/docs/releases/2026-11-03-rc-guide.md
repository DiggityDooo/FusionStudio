# Fusion Studio 0.19.0-rc.1 — local candidate guide

Windows candidate uses installed Blender 5.2 for conversion, native scene rendering and delegated operations. Blender, commercial applications and private DAZ content are not bundled. Keep the complete `win-unpacked` folder together.

## Start and save

Launch `Fusion Studio.exe`. Data, saved project versions, connection settings and logs live in the adjacent `Fusion Data` directory. Existing releases and their projects remain separate. Open an existing `.fusion` through File → Open; Save creates a new project version.

Core workflow: create/import → edit or sculpt → shape/pose → garment preview → undo/redo → save/reopen → render/export. Garment simulation remains an uncalibrated preview; portrait/hair realism and production cloth are not certified by this candidate.

## Import assets and presets

- Blender: choose preserved native rendering or editable interchange in Import Compatibility. Preserved scenes retain native rendering; evaluated viewport proxies and converted mesh/rig copies have the reported limitations. Native shaders, procedural logic and instancing are not generally editable through interchange.
- Interchange uses the saved active Blender scene. Supported modifiers bake on unskinned meshes; meshes with rigs or shape keys retain base topology and report skipped non-armature stacks. Preserved mode provides evaluated appearance for those cases. Large imported scenes keep adaptive viewport fog outside the framed bounds.
- DAZ: add the content-library root containing `data`, `People` and `Runtime` through Assets → Add library when needed. DUF and DSF share direct inspection/import. Select an imported asset before importing a pose, shape or material preset.
- Presets check source family, verified joint axes, morph source identity and material groups. Requested missing base-resolution morphs are searched only inside the selected geometry's own Morphs tree, with bounded counts. An ambiguous or incompatible preset is blocked without an edit.
- Material presets support base color/texture, scalar opacity, roughness and metallic values. Iray layers, additional texture channels, DAZ HD, grafts, general ERC parity, TriAx/dual-quaternion parity and strand hair remain unsupported or approximate. Referenced base-resolution morphs and general-weight rigs have specific tested workflows.
- OBJ inspection inventories MTL/textures and reports missing files. GLB/glTF, FBX, OBJ, STL and PLY have tested exchange subsets. USD and Alembic certification is limited to the demonstrated static subset; composition, variants and general animated caches are not certified.

Imported clips are retained, but independent selection of overlapping actions is not certified by this candidate.

Retain `.fusion` for Fusion controls and source attachments. Exchange exports do not replace the native project or guarantee universal lossless roundtrips. Native proprietary formats without verified adapters remain preservation-only.

## Models & Connections

Open **Models & Connections** in the top menu. Save a name, adapter, base URL and model ID, then use Test connection. Model runtimes and weights are supplied by the user.

| Adapter | Example base URL | Model field |
|---|---|---|
| OpenAI-compatible API | `http://localhost:1234/v1` | Model ID configured by that local server |
| Ollama | `http://localhost:11434` | An already installed model name |
| Compatible cloud API | Provider's HTTPS API base | Model ID enabled for that account |

Optional API keys are encrypted through Windows-backed Electron storage. Leave the key field blank to retain an existing key; Remove stored key clears it. Other provider protocols require a compatible gateway.

Chat sends only the entered conversation. It does not upload scene assets or automatically execute edits. Cancel stops the active request; Clear chat removes in-memory conversation. Profiles survive restart; conversation does not. Model-generation/retopology preview tools elsewhere are not made into real model-backed generation by adding a chat profile.

## MCP access

MCP is off by default. Enable it in Models & Connections, choose a free local port, and copy client configuration. **Allow scene edits** controls whether external AI clients may change the scene. The app must remain open. Clients need Streamable HTTP and the displayed bearer credential.

Tools: `scene_inspect`, `selection_inspect`, `selection_set`, `primitive_add`, `object_transform`, `history_undo`, `history_redo`. Every write requires current `projectId` and `revision` from inspection or the preceding result. Transforms use meters, degrees and scale multipliers; absolute component values are bounded to one million. Existing operator locks, compatibility and undo remain active. No arbitrary Python, shell, filesystem access or external MCP-server client is exposed.

## Evidence

Release report and per-run receipts identify the executable, source fingerprints, original-file hashes, fixture results and known limits. Private source assets and derived test outputs remain local and outside the package. Live external model providers are unverified unless a configured provider is explicitly recorded; deterministic localhost protocol fixtures cover the supplied adapters.
